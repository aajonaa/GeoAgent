# Native scientific image assets

These four tools use the same canonical implementation and schemas in direct
Python calls and the current GeoAgent runtime. There is no alternate algorithm
adapter and no model-written UI/action JSON protocol.

```python
from pathlib import Path
from geological_agent.scientific_imaging import operate

result = operate("GeoRasterIndexAnalysis", {
    "path": "bands.tif", "output_dir": "ndvi-result", "index": "NDVI",
    "bands": {"red": 1, "nir": 2},
    "calibration_source": "Actual dataset metadata and processing version"
}, workspace=Path("/absolute/existing/task-directory"))
```

`args` is a dictionary conforming to `input_schema`, not a serialized JSON
string. Ordinary HTTP JSON decoding belongs to the transport. The `workspace`
argument supplies the existing filesystem boundary, not an LLM-controlled input.
The old `geotool.domain_worker` is not the entry point for these assets.

| Tool | Inputs and method | Scientific output |
| --- | --- | --- |
| GeoRasterIndexAnalysis | Calibrated multispectral GeoTIFF, explicit band roles, optional aligned QA mask | NDVI/NDWI/NBR GeoTIFF, interval statistics, aligned previews |
| GeoRasterChangeAnalysis | Comparable calibrated single-band rasters on exactly the same grid, unit and threshold | After-minus-before GeoTIFF, numerical interval statistics and previews |
| GeoMapColorExtract | Oriented map image, map-only ROI, explicit legend labels/colors/tolerances | Candidate mask/polygons, overlay and statistics; pixel coordinates unless an actually aligned reference raster is supplied |
| GeoPlotDigitize | One colored curve, plot ROI, two actual tick anchors per axis, units | CSV, selected-point overlay and reconstructed plot; ambiguous columns omitted without interpolation |

Each result includes `analysis_type`, `manifest_path`, `outputs`, `statistics`
and `warnings`. Output references contain path, SHA-256, media type and role.
`analysis.geoanalysis.json` records input hashes, parameters, layers, grid,
statistics and limitations. Preserve all of it. PNGs are display products;
scientific raster values are in GeoTIFF, curve values in CSV.

All paths are workspace-relative, source files are preserved, and output
directories must be new. Current deployment allowances are 8 MiB per input,
20 million pixels and 48 MiB per generated bundle. Oversized inputs are rejected,
not silently resized; use an explicitly documented subset. Operations validate
schemas, paths, finite values, grids and calibration. Direct errors are
`ToolFailure` with `code`, `message` and `retryable` fields. Fix the cause before
retrying; do not blindly repeat or fabricate missing inputs. External network
access is not required during computation.

## Environment and acceptance

The accompanying requirements file records the versions used on A100. Python
3.12 is the tested interpreter. Install dependencies into the actual execution
environment and make this repository importable. Project code license/provider
and the receiving platform's protocol version still require owner confirmation;
catalog registration does not resolve those fields or certify scientific validity.

`catalog/source_delivery/examples.json` contains runnable examples referring to
explicitly synthetic inputs generated by `source_asset_checks.helpers.create`.
These are acceptance fixtures, not real research datasets. The current-runtime
acceptance entry is:

```bash
python -m pytest tests_local/test_professional_catalog.py tests_local/test_scientific_imaging.py
```

It invokes all source candidates through the actual native runtime, checks
schemas, scientific values, files, provenance, asset classification and Skill
references. Direct-call cases independently exercise the same implementation.
The three Skill documents in `catalog/skills` are byte-identical delivery
copies of their canonical runtime documents, with a regression assertion to
prevent divergence. Full workflow and browser acceptance remain separate gates.
